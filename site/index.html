Agent Spark

Seven decisions stand between a customer and their first Copilot Studio agent. Make them once.

Every new agent starts with the same assembly job: installer docs, pac command references, folder conventions, sample agents, skill formats, evaluation setup, governance guidance. That work gets repeated per customer and produces a different answer every time. Agent Spark moves those decisions into versioned content you can read, diff and own rather than advice you have to reassemble from seven places.

This is a pre-alpha concept repository. The templates and skills are usable by hand right now, with no tooling at all. The agentspark CLI that is meant to wrap them does not exist yet, and this page is not going to imply otherwise.

You have set this up before

A customer wants an agent that answers questions from their handbook. Straightforward enough. So you open the installer docs, then the pac command reference, then a sample agent someone shared, then whatever folder layout the last project used because nobody wrote one down. Somewhere in there you decide how instructions are structured, what a skill file looks like, whether evaluations exist at all, and who signs off before it is published.

None of those decisions are hard. All of them are load-bearing. And you will make every one of them again for the next customer, slightly differently, because there was nothing to copy from except your memory of last time.

That is not a documentation problem, and more documentation will not fix it. The decisions were never written down in a form a machine could check or a reviewer could diff, so each project quietly re-litigates them and the results drift apart.

How it works

Three steps, all of which work today by hand. There is no agentspark CLI to install, because it does not exist yet.

  1. Copy a scenario template

    templates/knowledge-assistant is a plain folder of Markdown and YAML: eight files covering instructions, security notes, a knowledge onboarding checklist, a baseline evaluation suite and deployment settings.

  2. Answer the variable checklist

    template.yaml names eight variables and what each one is for, from the agent identifier down to the escalation path a user gets when no approved source answers their question. The checklist is repeated at the top of the template README.

  3. Author the result in Copilot Studio

    You end up with instructions, an attached skill, a knowledge contract, baseline evaluations and a security note, before writing a line of agent content. deployment.yaml ships with publishing disabled.

What the CLI is meant to add later is the wizard around step two, not a different step two.

Three kinds of content, one contract

Templates, skills and schemas are not three separate offerings. The schemas are what make the other two reviewable, which is the entire point: content nobody can validate is just a folder of opinions.

  • Templates

    A whole scenario, not a snippet

    knowledge-assistant@0.1.0 generates eight files and declares its own compatibility, governance profile and risk posture in the manifest. It attaches no write tools, so the read-only claim is structural rather than a promise in a README.

  • Skills

    Behaviour with its failure modes written down

    answer-with-sources@0.1.0 ships seven guardrails, an explicit do-not-use-when list, a failure-behaviour table, and positive, negative and ambiguous worked examples. Most skill files describe the happy path and stop.

  • Schemas

    The part a machine can check

    Four JSON Schemas at agentspark.dev/v1alpha1 cover the agent project, template, skill and evaluation manifests. A manifest that claims a file must actually have one, and a compatibility flag that says verified must have a recorded round trip behind it.

Treat every agentspark command you see in this repository as a specification, not as software you can run. The command surface lives in the PRD because writing the interface down first is how you find out the interface is wrong, but nothing has been built against it and it has not been validated against an installed pac CLI.

That last number is the honest one, and it is on the page for the same reason the template manifest carries verified: false: a status that flatters the project is a status nobody can use. It changes when there is a real round trip against a real environment to point at, and not before.

Use it today, without the CLI

The Knowledge Assistant template is a plain folder. Copying it is the whole install step. 

$ git clone https://github.com/RagnarPitla/Agent-Spark
$ cp -r Agent-Spark/templates/knowledge-assistant ./my-agent
$ $EDITOR my-agent/README.md
# the variable checklist is at the top of that file

Replace the eight variables, then author the result in Copilot Studio by hand. You are not locked in to anything: the output is Markdown and YAML you now own, in a folder, with no tool required to open it and none required to leave.

And one thing you can actually run

The schemas are not decorative. The repository validates its own content against them on every push, and the same check runs locally against whatever you have edited. 

$ npm run validate

Agent Spark validator
  files scanned:      61
  manifests validated: 6
  schema             pass
  references         pass
  secrets            pass
  ascii              pass

PASSED.

That is the whole toolchain today: one validator, no install step beyond git clone, and no agent content generated for you yet.

Why not just start from a sample

Compared with an official sample agent

Samples are built to demonstrate a capability, and they are good at that. What they deliberately leave out is everything around the capability: no evaluation suite, no security note, no governance profile, no statement of what the agent must never do. Those omissions are correct in a sample and expensive in a starting point, because they are exactly the parts a reviewer will ask about.

Compared with your own internal starter

Most teams doing this at volume already have one, and it usually works. It also usually lives in one person's head or one team's drive, carries no version, and has no way to tell you it has drifted from the platform. A starter with a schema behind it can fail a build. A starter in a shared folder can only disappoint you later.

The unit of reuse here is a reviewed decision, not a code sample, which is why every template and skill carries an owner, a semantic version, a licence, a provenance statement and a review-by date.

What this is not

Agent Spark is an unofficial community project. It is not a Microsoft product, it is not covered by Microsoft Support, and it does not reimplement any part of the Copilot Studio runtime, harness or orchestration engine. It calls public, documented interfaces and nothing else.

Where the line sits, from the repository README.
Agent Spark ownsCopilot Studio owns
Developer experience, wizard, promptsRuntime, harness, orchestration
Generated files on your diskEnvironment state and agent state
Plan, dry-run, validation, reportsGovernance enforcement, DLP, licensing
Template and skill catalogSupported lifecycle behaviour of pac copilot

It never bypasses tenant administration, environment policy, DLP, authentication, licensing, consent or approval. Where a policy blocks an action, Agent Spark reports it and stops. Routing around a control that an administrator deliberately configured is not a feature, and a tool that offers it is one incident away from being banned outright.

  • Publishing is disabled by default in generated deployment settings
  • The starter template attaches no write tools at all
  • Generation connects no knowledge source and uploads nothing
  • Every template and skill carries provenance and a review-by date

Frequently asked questions

Can I install it?

Not as an agent generator. There is no published package and no executable named agentspark. What works today is git clone plus copying a template folder, which needs no installation because it is Markdown and YAML, and npm run validate, which checks that content against the schemas.

Is this a Microsoft product?

No. It is an unofficial community project under the MIT licence, not covered by Microsoft Support, and it does not speak for Microsoft. Views in this repository are the author's own.

Will it change things in my tenant?

Nothing here can, because nothing here executes. The template's own default is local-first, which performs no tenant operations, and the deployment settings it generates have publishing disabled. When a CLI does exist, the boundary above is the contract it has to hold to.

Why publish a repository with no working tool in it?

Because the content is the hard part and it is already useful. A reviewed template with evaluations and a security note saves real time whether or not a wizard wraps it. Building the wrapper first would have meant guessing at what it should generate.

It also makes the specification reviewable before anyone commits engineering time to it, which is cheaper than discovering the command surface is wrong after it is built.

Is "Agent Spark" the final name?

No, it is a working name. It has not cleared trademark review or npm name availability. ADR-0004 in the repository records the alternatives that were considered and why each was rejected.

Can I contribute a template or a skill?

Yes, and the bar is written down in CONTRIBUTING.md rather than left to a reviewer's mood. Every template and skill needs a named owner, a semantic version, a licence and provenance statement, worked examples and evaluations. Contributions that fail schema validation, contain a likely secret, or use non-ASCII typographic characters in Markdown are rejected automatically.

How is this different from just writing good documentation?

Documentation tells you what to do and then cannot tell whether you did it. A manifest with a schema behind it can fail a build when a referenced file is missing, when a compatibility flag claims a verification that never happened, or when a template drifts from the contract it declared.

The prose still matters, and there is plenty of it here. The difference is that the parts a machine can check are checked by a machine, so review effort goes to the parts only a human can judge.

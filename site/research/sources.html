S01 / Vendor measurement

GPT-6 Astra: A new generation of intelligence

OpenAI / 2026 announcement; accessed 7 September 2026 (8 September UTC)

The public model name is GPT-6 Astra, compared with GPT-5.6 Sol. OpenAI reports 72.6 versus 65.7 on OSWorld 2.0 v2026.08.08, offline set, partial score, and describes a separate Codex harness speed update. Its latency comparison is explicitly a simulation.

What this does not establish: These are vendor-reported results under described research settings, not an independently reproduced enterprise deployment. Partial score is not the percentage of complete workflows. The simultaneous model and harness changes do not isolate either causal contribution. Maximum-effort scores and production behavior can differ.

S02 / Product documentation

Computer Use

OpenAI developer documentation / Living documentation, accessed 7 September 2026

In supported regions, desktop Computer Use is documented for macOS and Windows in ChatGPT Work and Codex. It can operate graphical applications; the documentation prefers dedicated plugins or MCP servers for data access and repeatable operations when available. OS permissions, app approvals and workspace controls are distinct.

What this does not establish: This describes desktop product surfaces, not automatic feature parity with every CLI, API, account or operating system. Windows operation uses the active desktop. Native-app changes may fall outside a project's review pane. App permission is not blanket permission for every consequential action.

S03 / Technical explanation

Unrolling the Codex agent loop

OpenAI / 2026 technical article, accessed 7 September 2026

Codex orchestrates user input, model inference, tool calls, tool results and context management. Its output can be changed files rather than only an assistant message. This supplies a concrete working definition of a harness.

What this does not establish: It is a dated implementation account. Specific API and context-management choices can change; the later Astra announcement describes further context changes. It is not evidence that all adapters share the same sandbox.

S04 / Vendor case study

Harness engineering: leveraging Codex in an agent-first world

OpenAI / 2026 case study, accessed 7 September 2026

The authors describe exposing a per-worktree application, DOM snapshots, screenshots, logs and metrics to Codex. They emphasize repository knowledge, mechanically enforced boundaries and feedback loops, and explicitly limit generalization beyond their engineered environment.

What this does not establish: This is a self-reported internal-product case study, not a randomized productivity study. Its estimated speedup is not an established return on investment for other enterprises. It does not demonstrate that GUI use caused all of the reported benefit.

S05 / Product documentation

Managed configuration

OpenAI developer documentation / Living documentation, accessed 7 September 2026

Administrators can constrain supported browser and computer-use surfaces, including origins, native app identities and approvals. The document distinguishes command-network controls from browser checks and other tool traffic, and warns that supported requirements differ by client and version.

What this does not establish: A configured allow rule does not install a plugin, grant OS permission, or replace action approval. A command proxy is not a universal egress or DLP boundary across native apps, MCP, cloud tools and connectors. Customer deployments require effective-policy testing.

S06 / Vendor measurement

How enabling two settings tripled our scores on the ARC-AGI-3 benchmark

OpenAI / 2026 experiment report, accessed 7 September 2026

For the same named GPT-5.6 Sol model, OpenAI reports public-set ARC-AGI-3 Relative Human Action Efficiency scores of 13.3 with the official harness and 38.3 with a Responses API harness retaining reasoning and using compaction. The task returns text representations of game frames. The report illustrates dependence on context handling as well as the model.

What this does not establish: The metric is action efficiency, not a percentage of enterprise workflows completed. This is a vendor comparison, not this paper's experiment. The two context changes are bundled, and the report also notes token-versus-character window accounting. It neither isolates all factors nor establishes desktop GUI use as necessary for intelligence.

S07 / Artifact inspection

Agent Spark repository snapshot

Ragnar Pitla / Agent Spark / Commit 0fa8c409a9ed79850b0159fca864ef0ac18e5dd1, 25 August 2026; inspected 7 September 2026

The inspected snapshot contains a scenario template, a skill, four JSON Schemas, validation and generation-proof scripts, and proposed CLI/package contracts. README, scripts/validate.mjs, scripts/proof-run.mjs and the manifests establish the boundary between content tooling and an unimplemented runtime.

S08 / Artifact inspection

Knowledge Assistant template manifest

Ragnar Pitla / Agent Spark / Pinned 25 August 2026 snapshot; inspected 7 September 2026

The manifest declares eight variables, eight output files, pinned skill content, publishing disabled, ownership and provenance. compatibility.verified remains false because its OS and harness claims exceed the reported round trip; comments explicitly distinguish delivery from behavior.

S09 / Repository-reported observation

Agent Spark compatibility observations

Ragnar Pitla / Agent Spark / Reports observations from 25 August 2026 with PAC 2.11.2 on macOS

The repository reports that generated instruction content reached a server-side draft with an identical SHA-256, and that some tenant effects differed from local command-name expectations. This illustrates why delivery receipts, target identity and published state need separate observation.

What this does not establish: These observations were not rerun for this paper. They concern a particular version and environment, are not proof of the current platform's universal behavior, and contain no behavioral or customer-ROI evaluation.

S10 / Design proposal

ADR-0003: Separate planning from execution

Ragnar Pitla / Agent Spark / Accepted design decision dated 24 August 2026, in the pinned snapshot

The project proposes reviewable plans followed by execution, serializable changes and checkpoints. It explicitly trades adaptive execution for predictability. The paper uses it to discuss how bounded adaptation would need a separate design decision.

What this does not establish: An accepted ADR is not implemented software. Checkpoints do not imply transaction rollback or exactly-once remote effects. The paper's adaptive-harness proposal does not silently amend this ADR.

S11 / Research paper

OSWorld: Benchmarking Multimodal Agents for Open-Ended Tasks in Real Computer Environments

Tianbao Xie et al.; NeurIPS 2024, Datasets and Benchmarks / Original OSWorld paper, arXiv revision 2, 30 May 2024; accessed 7 September 2026

The original benchmark studies desktop, browser, file and cross-application tasks in virtual machines, using task-specific state evaluators. It exposes grounding, application-knowledge and multistep difficulties. Observation variants include screenshots, accessibility trees and Set-of-Marks.

What this does not establish: Revision 2 of this paper is not OSWorld 2.0. Its task set, grading and historical results must not be transferred to the Astra comparison. It is not inherently pixel-only, permits fractional rewards, and is not an enterprise field study. A screenshot-only future is an author conjecture, not a result established by the benchmark.

S12 / Research paper

WebArena: A Realistic Web Environment for Building Autonomous Agents

Shuyan Zhou et al.; ICLR 2024 / ArXiv revision 4, 16 April 2024; accessed 7 September 2026

A resettable environment of realistic web applications connects natural-language intent to measurable state changes. It supports HTML, accessibility-tree and screenshot observations and element-targeted or coordinate actions. Its evaluation includes answer, URL and page-content checks.

What this does not establish: Controlled replicas and curated intents do not measure live-site robustness or customer economics. Some semantic answer matching uses an LLM judge. Describing every evaluation as deterministic or every observation as visual would be inaccurate.

S13 / Research paper

WorkArena: How Capable are Web Agents at Solving Common Knowledge Work Tasks?

Alexandre Drouin et al.; ICML 2024, PMLR 235:11642-11662 / 2024 proceedings; arXiv revision 5 also read, 23 July 2024

WorkArena studies 33 atomic task types in ServiceNow, including forms, lists, knowledge, catalogs, dashboards and navigation. Its interface and memory ablations show that extra coordinate capabilities or retaining previous reasoning did not help uniformly in the tested configurations; memory could reinforce mistakes.

What this does not establish: It is a platform-specific benchmark, not a customer study. The historical ablations do not prove that vision or memory is generally harmful, and should not be generalized to different 2026 models or context-retention mechanisms.

S14 / Research paper

WorkArena++: Towards Compositional Planning and Reasoning-based Common Knowledge Work Tasks

Leo Boisvert et al.; NeurIPS 2024, Datasets and Benchmarks / ArXiv revision 2, 5 February 2025; accessed 7 September 2026

The study presents 341 workflows in two formulations, yielding 682 tasks. One formulation provides explicit instructions; the other requires recovering a procedure from a knowledge base. Error analysis includes mistaken goals, invented actions, imagined progress and ineffective repetition.

What this does not establish: The workflows and company procedures are curated on one platform. The onboarding example is a benchmark analogue, not proof of a cross-application customer deployment. Its historical scores are not current frontier-model performance claims.

S15 / Research paper

OSWorld-MCP: Benchmarking MCP Tool Invocation In Computer-Use Agents

Hongrui Jia, Jitong Liao, Xi Zhang et al.; authors report ICLR 2026 acceptance / ArXiv revision 2, 11 November 2025; accessed 7 September 2026

A study of 361 OSWorld-derived tasks and 158 curated application tools compares GUI-only with GUI-plus-MCP configurations. Under its GUI-Owl setup, 15/50-step limits and three runs per configuration, structured tools generally improve completion and reduce action counts. It is direct evidence for studying hybrid interfaces.

What this does not establish: This is not an API-only versus hybrid comparison. Equal action budgets are not equal latency or cost budgets; curated tool coverage limits generalization. Tool Invocation Rate incorporates success into its definition, so its association with accuracy is not an independent causal result. The cited text is the arXiv revision; final proceedings were not independently inspected.

S16 / Benchmark maintenance report

OSWorld-Verified maintainer report

OSWorld / xlang maintainers / Maintainer report, accessed 7 September 2026

The maintainers document benchmark repairs involving ambiguous instructions, valid solutions rejected by evaluators, timing, websites and environment failures. The report motivates pinning tasks, graders and infrastructure instead of treating a benchmark name as a complete specification.

What this does not establish: This report concerns repairs to the original OSWorld line. It does not establish the task set or configuration of OSWorld 2.0 v2026.08.08. Evidence of a grader defect is not proof that every model score is invalid.

S17 / Research paper

tau-bench: A Benchmark for Tool-Agent-User Interaction in Real-World Domains

Shunyu Yao, Noah Shinn, Pedram Razavi and Karthik Narasimhan; ICLR 2025 / ArXiv revision 1, 17 June 2024; accessed 7 September 2026

Synthetic retail and airline tasks combine a simulated user, policies, API tools and mutable databases. The paper introduces pass^k for all-k-trials success and distinguishes it from pass@k. It explicitly notes that a successful final-state reward can conceal a policy violation such as acting without confirmation.

What this does not establish: Correct final state does not establish a compliant action path. Simplified domains and an LLM user simulator limit realism. The paper also shows semantic and policy errors without a GUI; removing visual difficulty does not solve agency.

S18 / Research paper

Measuring AI Ability to Complete Long Software Tasks

Thomas Kwa et al.; METR; NeurIPS 2025 / ArXiv revision 4, 10 July 2026; accessed 7 September 2026

The study evaluates model-plus-scaffold systems on software, cybersecurity and ML-engineering tasks, primarily through Python and Bash. It relates success probability to human task duration and discusses messier tasks, resource limits and external validity.

What this does not establish: A time horizon is a fitted human-duration measure at a specified success probability, not autonomous wall-clock runtime. The result is not an enterprise reliability guarantee or proof of AGI. Dynamic, multi-actor workflows without automatic graders can differ materially.

S19 / Theoretical paper

Universal Intelligence: A Definition of Machine Intelligence

Shane Legg and Marcus Hutter; Minds & Machines 17(4), 391-444 / 2007; arXiv revision 1, 20 December 2007

A proposed formalization models agents acting and receiving observations and rewards across environments. The communication channels are abstract rather than intrinsically graphical, helping separate environment interaction from one particular interface.

What this does not establish: This is a theoretical proposal, not a universally accepted operational AGI test, a GUI requirement, or evidence that any deployed model meets the definition.

S20 / Research paper

The BrowserGym Ecosystem for Web Agent Research

Thibault Le Sellier de Chezelles et al.; authors' publication entry identifies TMLR 2025 / ArXiv revision 4, 28 February 2025; accessed 7 September 2026

BrowserGym supplies a common environment and experiment-management system with DOM/accessibility data, screenshots, actions, errors and reproducibility tooling. It explains how observations, tools and scaffolds affect the evaluated system, and discusses drift, localization, bot detection and shared-state limitations.

What this does not establish: Its comparison does not use visual inputs outside VisualWebArena; its tables must not all be described as vision-based evaluations. Some table entries are not newly executed runs. Publication status was checked against the authors' repository because the OpenReview page presented a browser challenge.

S21 / Product documentation

Harnesses in Copilot Studio

Microsoft Learn / Page updated 5 September 2026; accessed 7 September 2026

Microsoft defines a harness as the runtime governing model calls, supplied context, interpretation and tool invocation. It documents different harnesses for different workloads, including file creation and editing for the GitHub Copilot harness.

What this does not establish: Agents and harnesses are not competing categories; a harness powers an agent. Do not combine capabilities from different harnesses into an assumed universal runtime or infer geographic rollout or GA from a page-update date. This is documentation, not a performance audit.

S22 / Product documentation

Automate web and desktop apps with computer use

Microsoft Learn / Page updated 3 August 2026; accessed 7 September 2026

The page documents Windows GUI interaction with virtual mouse and keyboard, including applications without APIs, and explicitly scopes its computer-use features to the standard harness. It describes credentials, logs, screenshots, HTTPS enforcement and application/website action restrictions.

What this does not establish: Maker-provided credentials are the documented default; sharing can expose the maker's execution authority. The action allowlist does not prevent opening an unapproved surface and is not a universal egress boundary. The documented controls and execution mode must be assessed for the actual deployment.

S23 / Product documentation

Configure where computer use runs

Microsoft Learn / Page updated 3 August 2026; accessed 7 September 2026

The page distinguishes hosted browser, Cloud PC pools and customer-managed Windows machines. Hosted-browser and Cloud-PC-pool sections carry preview notices, while customer-managed machines have their own registration and software prerequisites.

What this does not establish: The hosted browser is not recommended for production and does not provide tenant Entra join, Intune management, enterprise-resource access or custom desktop applications. Those restrictions must not be transferred indiscriminately to every execution mode. The source does not establish universal geographic or tenant availability.

S24 / Product documentation

FAQ for the computer use tool

Microsoft Learn / Page updated 20 May 2026; accessed 7 September 2026

The FAQ describes a perception-reasoning-action loop and documents variable outcomes, timing and visual sensitivity, difficult controls, loops and prompt-injection risks. It explicitly warns that model-triggered supervision is probabilistic, not a guaranteed approval gate or safety fail-safe.

What this does not establish: The FAQ excludes making financial transactions among intended uses. A human approval prompt does not erase that boundary. Its dated success figures lack enough experimental detail for a current ranking, enterprise guarantee or SLA; this paper does not use them.

S25 / Risk-management guidance

Artificial Intelligence Risk Management Framework: Generative Artificial Intelligence Profile

Chloe Autio et al.; NIST AI 600-1 / Published 26 July 2024; accessed 7 September 2026

MS-2.3-003 recommends sharing predeployment results with release-approval authorities. MS-2.5-001 warns against extrapolation from narrow or anecdotal assessments. MS-2.5-006 recommends revisiting guardrails and original deployment-safety judgments.

What this does not establish: Voluntary, context-dependent guidance, not certification of an artifact or a prescribed harness architecture. A later update to a publication landing page does not create a new edition of the 2024 profile.

S26 / Risk-management guidance

LLM06:2025 Excessive Agency

OWASP GenAI Security Project / 2025 edition; public source pinned to commit 79c180515d6500c8a66627fa8343bd514c464380

The guidance recommends minimum necessary functionality and permissions, user-context execution, approval for high-impact actions, and authorization enforced downstream rather than entrusted to an LLM's judgment. Relevant mitigation passages are at lines 64-78.

What this does not establish: This is mitigation guidance, not a finding that a particular product is vulnerable or that a declared policy is enforced. The pinned project source avoids the website's misleading legacy URL slug.

S27 / Technical documentation

Terraform CLI: plan command

HashiCorp / Living documentation, accessed 7 September 2026

Established prior art for previewing intended changes, optionally saving a plan, and applying a reviewed plan later. The documentation warns that changes in the target system can invalidate expectations from an earlier speculative plan.

What this does not establish: This is not evidence that an LLM's proposed trajectory predicts future GUI state, that planning has no possible incidental effects, or that a previously approved action remains authorized after its assumptions change.
